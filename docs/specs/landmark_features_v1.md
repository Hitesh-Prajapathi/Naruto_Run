# Landmark feature spec v1 (`FEATURE_SPEC_VERSION = "1.0.1"`)

Changelog: **1.0.1** -- slot assignment ranks non-finite handedness scores as 0.0 (section 3.1),
which makes the "keep the two best hands" cut a total order that Python and TypeScript agree on.
The feature vector itself is unchanged for every input whose scores are finite. 1.0.0 -- initial.

Reference implementation: `src/narutocv/features/landmarks.py`.
Machine-readable listing of every feature: `docs/specs/landmark_features_v1.json`
(generated by `export_feature_spec`). The TypeScript port must reproduce the
vector below to within 1e-4 (float32 output, float64 internal math).

All arithmetic is float64 using only `+ - * /`, `sqrt`, `atan2`, dot and cross
products. The final vector is cast to float32. There is no `acos`, no SVD, no
sorting other than the ones named below.

## 1. Input

Up to N hands, each:

| field | meaning |
|---|---|
| `landmarks` | 21 x (x, y, z), MediaPipe HandLandmarker normalised image landmarks (`x` in [0,1] of width, `y` in [0,1] of height, `z` same scale as `x`) |
| `handedness` | `"Left"` or `"Right"` exactly as reported by the landmarker, on the same image orientation used in training (MediaPipe assumes a mirrored selfie image) |
| `score` | handedness score in [0,1] |
| `world` | optional 21 x 3 world landmarks. **Unused in v1.** |

`image_size = (width, height)` in pixels.

Landmark indices (MediaPipe): 0 wrist; thumb 1-4 (CMC, MCP, IP, TIP);
index 5-8; middle 9-12; ring 13-16; pinky 17-20 (each MCP, PIP, DIP, TIP).

## 2. Canonicalisation (`canonicalize_hand`)

1. **Pixel space:** `P[i] = (x*W, y*H, z*W)`. This is mandatory: geometry in
   normalised coordinates is wrong for non-square images.
2. **Validity:** if any coordinate is non-finite, the hand is *degenerate*.
3. **Mirror:** if the (slot-assigned, see section 3) handedness is Left, `P[i].x = -P[i].x`
   (reflect through x = 0; translation is removed by the next step so the
   reflection axis does not matter). Mirroring happens before the palm frame is
   built, so a mirrored right hand labelled Left reproduces the original input
   exactly.
4. **Palm size:** `s = |P[9] - P[0]|` (wrist to middle MCP). If `s < 1e-6` the hand
   is degenerate.
5. **Palm frame** (in mirrored space, wrist `w = P[0]`):
   - `y = (P[9] - w) / s`
   - `x_raw = P[17] - P[5]` (index MCP to pinky MCP); `x_raw -= (x_raw . y) y`
   - if `|x_raw| < 1e-6 * s` (lateral axis undefined): `k = argmin_i |y_i|`
     (lowest index on ties), `e = unit vector k`, `x_raw = e - (e . y) y`
   - `x = x_raw / |x_raw|`, `z = x cross y` (palm normal)
6. **Canonical coordinates:** `C[i] = ((P[i] - w) . x, (P[i] - w) . y, (P[i] - w) . z) / s`.
7. **Frame in original space** (needed for inter-hand features): the axes are
   reflected back, `X = (m*x.x, x.y, x.z)` etc. with `m = -1` for mirrored hands.
   `Z` is then the *physical* palm normal for both hands, consistent across
   left and right.

Degenerate hands are removed before slot assignment and are never counted as
present. Their features are zeros.

## 3. Slot assignment (`assign_slots`)

Slots: `L` (index 0) and `R` (index 1).

1. Drop degenerate hands. If more than two remain keep the two with the highest
   `score` (ties: earlier input), preserving input order. A non-finite score
   (NaN, +inf, -inf) ranks as `0.0` for this cut, exactly as it counts as 0 in
   `meta.mean_score` (4.3); the sort key is `(-rank_score, input_index)`, a total
   order. (1.0.0 sorted on the raw score, so a NaN made the result depend on the
   sort implementation.)
2. One hand: slot by its label.
3. Two hands with different labels: slot by label.
4. Two hands with the *same* label: the hand with the smaller mean x over its 21
   landmarks (normalised coordinates) goes to `L`, the other to `R`; equal means
   keep input order.

Why the tie-break: MediaPipe frequently mislabels hands in mirrored or
interlocked poses (both hands labelled `Right`, or `Left`, or flipping frame to
frame). Taking labels at face value would put both hands in one slot (losing
the other slot) and would mirror one hand wrongly. Position is a robust, stable
signal: because MediaPipe assumes a mirrored selfie image, the `Left` hand is the
one with smaller x. This assumes that training data and the browser feed the
landmarker the same image orientation. If the browser flips the video, flip it
the same way in both.

The *slot*, not the raw label, decides mirroring (Left slot => mirrored).

## 4. Feature vector (84 floats)

Layout: `[L hand (25) | R hand (25) | inter-hand (30) | meta (4)]`.

### 4.1 Per hand (25), computed on canonical coordinates `C`

Angles are radians. `angle(u, v) = atan2(|u x v|, u . v)` in [0, pi].

| count | name | formula id | definition |
|---|---|---|---|
| 15 | `{slot}.flex.{finger}.{k}` (k = 0..2) | `bone_angle` | finger chain `c = [0, a, b, c, d]` (wrist then the four joints); for joint `j = c[k+1]`: `angle(C[j] - C[prev], C[next] - C[j])` with `prev = c[k]`, `next = c[k+2]`. 0 = straight. Order: thumb, index, middle, ring, pinky, three each |
| 5 | `{slot}.abd.{finger}` | `abduction_angle` | proximal bone `d = C[end] - C[start]`, `atan2(d.x, d.y)` (signed lateral splay in the palm plane). Bones: thumb 2->3, index 5->6, middle 9->10, ring 13->14, pinky 17->18 |
| 5 | `{slot}.tip_palm.{finger}` | `tip_palm_dist` | `|C[tip] - mean(C[0,5,9,13,17])|` (palm size units). Tips 4, 8, 12, 16, 20 |

Chains: thumb 0,1,2,3,4; index 0,5,6,7,8; middle 0,9,10,11,12; ring 0,13,14,15,16;
pinky 0,17,18,19,20.

### 4.2 Inter-hand (30), only when both slots are present (else zeros)

Quantities use *original-space* pixel positions of the hands:
`O[i] = wrist + (C[i] * s) . frame` (rows of `frame` = X, Y, Z from 2.7), and
`m = (s_L + s_R) / 2`.

| count | name | formula id | definition |
|---|---|---|---|
| 3 | `inter.wrist_vec.{x,y,z}` | `wrist_vec_shared_frame` | `((wrist_L - wrist_R) / m)` expressed in the R-slot hand's original-space frame: components `(X_R . v, Y_R . v, Z_R . v)` |
| 25 | `inter.tip_dist.L{fl}_R{fr}` | `tip_tip_dist` | `|O_L[tip_fl] - O_R[tip_fr]| / m`; row-major, rows = L-slot fingers, columns = R-slot fingers (thumb..pinky) |
| 1 | `inter.normal_angle` | `palm_normal_angle` | `angle(Z_L, Z_R)` |
| 1 | `inter.palms_facing` | `palm_facing` | `u = unit(c_R - c_L)` with `c` the original-space mean of landmarks 0,5,9,13,17; `1.0` if `Z_L . u > 0.2` and `Z_R . u < -0.2`, else `0.0` (zero vector `u` gives 0) |

The 0.2 margin keeps flat, co-planar hands (dot product exactly 0) away from the
decision boundary.

### 4.3 Meta (4)

`meta.hand_count` (0, 1, 2, after dropping degenerate / extra hands),
`meta.present_L`, `meta.present_R` (0/1), `meta.mean_score` (mean `score` of
present hands, non-finite scores count as 0; 0 if no hands).

## 5. Invariances (tested)

Features are invariant (tol 1e-4) to translation, uniform scale and in-plane
rotation of the input (applied in pixel space), and per-hand features are
identical for a right hand and its mirror image labelled Left. Output is always
finite and always has length 84 regardless of hand count or degenerate input.

## 6. Known limitations (v1)

- `z` from the landmarker is noisy; depth-dependent features (normals, tip
  distances) inherit that. A v2 may use world landmarks.
- `inter.palms_facing` is a hard threshold; it is a convenience flag for the
  model, not a calibrated quantity.
- Inter-hand features use the R-slot frame as reference, so they are not
  mirror-symmetric under whole-scene mirroring (not required).
